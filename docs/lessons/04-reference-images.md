# 04 参考图

## 这一步做什么

为需要新建的部件冻结**外观风格**，同时把**尺寸**和**载荷链**单独确定下来。参考图不是工程图，它只回答"长什么样"；"多大、怎么受力"由尺寸表和载荷链来回答。

## 输入 / 产物 / 完成判据

- 输入：方案预览里的工程决策、复用资产的实测几何（如 P1-B）、外部标准（如 SLAS 板尺寸、Franka Hand 规格）。
- 产物：`board/*.webp`、`prompts/*.txt`、`reference.json`（每张图对应的模型、请求尺寸与实际尺寸、是否已查看、与设计的差异）、`dimensions.md`（每个尺寸都标明来源类别）、`load_path.svg`、`index.html`（审批点②页面，由 `wb review` 生成）。
- 完成判据：`wb gate <项目> reference` 判 PASS；用户在审批点②确认参考图，并同时确认 plan。

## 工具与调用方式

- imagegen：多张图在后台并行生成。所有提示词共用一段风格前缀（材质、配色、底色、"无文字、无 logo"），后面再接各自的视角和状态描述。
- 生成的 PNG 立即转成 WebP，然后删除 PNG。
- 用 Pillow 把所有图拼成一张联系表，一次看完，并逐张记录与设计的差异。
- 审批页用 `uv run wb review <项目>` 从项目文件生成，不手写。

## 标准做法

1. 门的铰链朝向、开门方向、隔板层数等要和已有的效果图、复用资产保持一致，并在提示词里写明。
2. 生成图与设计的差异不需要重新生成，只要在 reference.json 里注明即可。图只冻结风格，尺寸以尺寸表为准。
3. 尺寸表每一项都标明来源类别（标准锚点 / 设计假设 / 实测），并写清依据。"实测"项尽量取自复用资产的几何数据，这样新旧资产可以直接对比。
4. 载荷链从工件一直画到地面，门单独画一条链。

## 踩过的坑

- 生成图会自作主张，比如画出 5 层隔板。这类偏差不必追求逐张修正，只需记录下来。
- 在 `/mnt/d` 上用 `shutil.copytree` 会因 copystat 被拒而失败，改用只复制文件内容的方式。
