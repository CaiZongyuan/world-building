# 06 仿真

**这是薄切片里问题最大的阶段**：14 次返工，名义流程连续 7 次 FAIL 才 PASS，还有 1 个负例没有触发。前面几个阶段没暴露的几何、布局、控制、数值问题，全部在这里集中出现。

## 这一步做什么

把复用资产和新建资产装配成一个 MuJoCo 场景，规划机械臂轨迹，跑名义流程和负例，用 plan 阶段冻结的门限判定结果，并把刚体位姿记录下来供渲染使用。

## 输入 / 产物 / 完成判据

- 输入：
  - `05-modelling/design.json`、`incubator.xml`
  - 复用资产：观察站、六孔板、Panda、底座
  - `03-plan/thresholds.json`
- 产物（`06-simulation/`）：
  - `scene.py`：MjSpec 装配
  - `plan_motion.py`：IK、轨迹，以及两类运动学初筛
  - `run_flow.py`：动力学运行和门限评估
  - `results/*.json`：名义流程和各负例的结果
  - `states_30fps.npz`：渲染用的刚体位姿
  - `scene_layout.json`：交给渲染阶段的布局
- 完成判据：`uv run --extra sim wb gate <项目> simulation`。名义流程 S1–S13 全部 PASS，所有负例都按预期判 FAIL。

## 标准做法（按顺序）

1. **先做运动学初筛，再跑动力学。** 沿参考轨迹逐帧摆好关节姿态，检查两件事：
   - 机器人与环境之间有没有接触（手指开度要按夹持状态设置）；
   - 门、抽屉的扫掠范围与静态环境之间有没有接触。

   整条轨迹查一遍约 8 s，而跑一次动力学要约 120 s，出了问题也更难定位。这里能发现的问题，都要在这里解决掉。
2. **关键位姿用多初值、带碰撞检查的 IK**：只接受与环境无接触（留 5 mm 裕度）的解，再从中选离舒适姿态最近的。大范围移动用关节插值；短距离直线动作才做笛卡尔跟踪。
3. **搬运带盖工件时，手爪姿态只允许绕竖直轴转动**。搬运段用"绕底座竖轴的圆弧加偏航插值"，不要用关节插值，否则工件会倾斜、盖会滑落。
4. **布局要按可达性来定**。取、放两个位置都应该让手爪径向朝外。如果出现"伸过去再回头"的姿态，说明布局有问题。对于朝外水平的手爪，可达高度有上限：本例在半径约 0.5 m 时只能到 z ≈ 0.70。
5. **控制方面**：
   - 位置执行器要加速度前馈：`ctrl = q_ref + (kv/kp)·q̇_ref`。
   - 机器人要开重力补偿（gravcomp）。
   - 复用设备的驱动参数要核对稳态误差，例如抽屉原来的 kp 会造成约 2 mm 的误差。
6. **接触数值方面**：开 `noslip_iterations`；夹持接触用更硬的 solref（本例为 0.002）；夹持力的大小要与穿透门限匹配。
7. **测量代码要对照门限原文写**，例如 S8 的目标点是"抽屉收回后的托槽"，S11 只统计"任务物体"。代码写错了就改代码，不改门限。

## 踩过的坑（附证据，详见项目 stage-log）

- **MjSpec**：
  - `attach_body` 只会带入 body 子树，源文件里的 `<exclude>` 不会跟过来。门因此和箱体卡住，停在 51.7°。
  - 子 body 会继承 frame 的旋转：观察站转了 −90°，板也跟着转了 90°，结果夹爪面对的是短边，永远夹不到。
- **Menagerie Panda**：
  - `right_finger` 自带绕 z 轴的 180° 旋转，自定义的手指零件要把 x 坐标取反。
  - 位置执行器有 kv 阻尼、没有前馈，跟踪运动中的参考会滞后约 0.07 rad。
  - 原装夹爪只有约 0.9 N 的余量；增益放大 20 倍后约 18 N，但 1.1 mm 的穿透超过了门限。最后用 noslip、加硬的指垫，以及 18 N 的夹持力，把穿透控制在 0.09 mm。
- **P3 原布局有干涉**：外门宽 0.7 m，扫过的范围会擦到机器人底座法兰角。P3 当年没有发现，因为没有做设备扫掠初筛。
- **偏置宽指改了 3 次**，起因都是水平放板时观察站抽屉前面板（比板底高 44 mm）这个约束：先缩短 TCP，再让指垫下沉 70 mm，最后把下垂腿外移，给定位墙留出余量。
- **软接触的摩擦蠕变**：板在指垫之间缓慢前滑了 6.6 mm，最后搁在了定位墙上。
- **负例必须真的能触发**：N3 v1（把盖的摩擦设为零）没有触发。后来用独立模型扫参数才弄清楚：盖裙把盖在水平方向锁死了，板倾斜 60°、搬运快 5 倍、2 N 侧向冲击下，盖的位移都小于 0.6 mm，危险本身就不存在。v2 改成"夹取高度偏高 11 mm"：指垫夹到盖裙，盖被提走，板留在原处，S5 = 1.2 m，按预期触发。

## 全流程实验室（cell-passaging-lab）新增经验

**可达性与构型**
- **先查姿态带**：手爪水平朝外、手掌朝上时，Panda 的 j6 会在 TCP 高出基座 0.18–0.34 m 这一段顶到下限，这段 IK 无解，不是求解器的问题。布局要让所有取放高度都落在同一条可解的高度带里（本例基座 0.85 m，取放 0.90–0.99 m），设备台面跟着这条带定。
- **构型族**：搬带盖工件时只能靠导轨平移和 j1 转动，所以取、放必须属于同一族构型。基座沿导轨和 TCP 错开（本例 0.25 m），朝南一族转 π 就是朝北一族；转身时按 j1 限位选 +π 或 −π。
- **预演的对称假设**：偏置宽指绕进入方向转 180° 后，手掌就到了板下面，不能算同一个抓取。`wb preflight` 里偏置指的位姿要标 `symmetric: false`。

**控制与约束（MjSpec）**
- 自建位置执行器必须设 `biastype = affine`，否则 `biasprm` 不生效，执行器的力等于 kp × 指令值，一开局就冲到挡块上。
- MjSpec 的铰链范围默认用度。design 里写的是弧度，要按 `spec.compiler.degree` 换算。
- **weld 的 data 有 12 个数**：anchor(3)、relpos(3，body2 在 body1 坐标系)、relquat(4)、torquescale 和一个保留位。新建 weld 的默认 anchor 是 (0, 1, 0)、relquat 全 0，要么在构建时写全 data（`to_xml` 会写成 `relpose`），要么在运行时按两者的实际位姿写入 `eq_data[3:10]` 再激活。
- **串联的软约束不要把最轻的件放在中间**：软约束的刚度按惯量缩放。weld 挂在"手 → 3 g 的盖 → 7 g 的管"这条链上，最轻的盖偏得最多，管相对手偏 2°。改成手直接 weld 到管身，盖经螺纹 weld 跟着管走。
- 压装件不要用"自由体 + weld"，把它的几何直接复制进父 body。适配器用 weld 时会和转子较劲，漂了 24 mm。

**接触**
- **接触数是性能的头号因素**：盖压在整块垫台上时，盖内几百个加强筋小凸块全部接触，产生 444 个接触，实时因子从 0.2 掉到 0.02。改成两根窄条只托盖裙后恢复。离心机的盖和适配器也是同理，要么排除接触，要么合并几何。
- **不往下丢东西**：软接触在撞击瞬间一定会穿透几毫米，过不了 S3（0.25 mm）。重件先压上 0.5 mm 再松手；轻件（吸头、管、盖）在支撑面上方 0.3 mm 松手。
- 小件（几克）用默认 solref 0.02 太软，统一改用 0.004。
- **对中靠几何，不靠力**：单向平夹块只能扶正一个方向。改成 V 形夹块（两块斜 45° 的板），两个水平方向都能对中。还有两个前提：衬面摩擦要明显小于 45° 斜面的自锁系数 1（本例取 0.2，用 MJCF `priority` 让衬面参数生效）；被推的件在座面上要能滑动。
- 运动学初筛不统计被夹着的工件。托盘挡边挂住搬运中的板这类问题，只能靠动力学发现，或者在初筛里把被夹工件也算上。

**分期开发与集成**
- 分期并行开发时，每期先用合成的起点开发，集成时再从上一期的真实终态重跑。本例集成时发现的问题有：
  - 上一期留下的龙门不在零位；
  - 上一期自己加的约束名在下一期的模型里不存在；
  - 被动设备的执行器指令会回零。
- 期末状态要存全：所有关节和执行器指令，按名字保存；最好直接存完整的 mjData 状态，`mj_getState(mjSTATE_INTEGRATION)` 加上 `eq_data`。各期用同一个模型时，接上就和一次跑完等价（`06-simulation/chain.py`）。
- **合并位姿要重采样**：各期的首个样本在 t = 0.5 ms，上一期的末样本正好在期末，直接拼接会在接缝处多出近乎重复的帧，渲染门的帧数（时长 × 30 + 1）就对不上。按 30 fps 网格取时间最近的样本，t 记网格时间。

## 阶段日志摘要

约 1.5 h，约 25 轮。名义流程连续 7 次 FAIL 后 PASS：穿透 0.09 mm，盖滑移 0.18 mm，支撑力 20.9 倍载荷，终态偏差 0.13 mm。负例 N1、N2 有效；N3 v1 失效，按 #7 重新设计为 v2 后有效，仿真验证门判 PASS，门限没有改。
