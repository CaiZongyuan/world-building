# 谁决定什么

这条流程刻意把人和 agent 的分工划得很清楚：**你决定方向，agent 决定工程细节**。这样你的注意力只花在只有你才能回答的问题上，而 agent 不会每遇到一个尺寸问题就停下来等人。

## 你：三次出场

| 时机 | 你看什么 | 你决定什么 |
|---|---|---|
| **需求访谈中** | 场景、流程、资产三张清单（范围大时有一页范围预览） | 范围对不对：有没有漏掉的区域、设备、工艺步骤；哪些复用、哪些新建 |
| **审批点①：方案预览之后** | 8 节方案页：目标、效果图、布局、设备、工艺步骤、阶段、风险、外部参考；以及运动学预演的结论 | 方案方向对不对。有意见就直接说，agent 改完重新发布 |
| **审批点②：参考图之后** | plan（冻结的门限、负例、分期）和参考图审批页 | 门限有没有覆盖你在意的风险；外观风格对不对。点头后，建模、仿真、渲染全程自主 |

需求访谈本身也要你回答几轮问题，但每一问都附推荐答案，回一句「按推荐」就等于全部接受。审批时具体看哪几样，见[审批时看什么](/skill/review)。

::: info 为什么是这三处
这是两个项目里实际收敛出来的。全流程实验室开工时，agent 只问了 9 个原则问题就开始做工具，你问「你不是应该先和我确认完整场景、流程、资产都应该包括哪些吗」，于是有了三张清单这一步。反过来，第一版方案页把夹爪、层位、外形尺寸列成「请用户确认」，你的反馈是「具体的尺寸问题需要 agent 自己解决，不要麻烦用户」。
:::

## agent：其余所有事

- **工程细节自己定。** 尺寸、夹具形式、布局、层位、控制参数，agent 自己查证、自己决定，写进方案页的「工程决策」和阶段日志，每项附理由和证据。推翻了先前的推荐也照此处理。
- **每个阶段先给阶段说明。** 输入、要做什么、用什么工具、怎么算完成、最可能出什么问题，几句话说清楚。
- **能查到的事实不问你。** 资产能不能编译、硬件是什么、历史场景能不能复现，先由子代理查清。
- **不写时间预估。** 只按阶段、工艺步骤和难度组织；阶段日志只记实测数据。

## 卡住时的处理顺序

判 FAIL 是常态（薄切片 01 的名义流程连续 FAIL 了 7 次才 PASS）。agent 按下面的顺序处理，**门限永不放宽**：

1. **复盘并重新设计。** 找根因，改设计或做法后重跑。失败记录全部保留。
2. **理想化，并如实标注。** 如果某个物理细节确实做不了（例如几克重的小件靠接触夹持数值不稳），改用理想化处理，标为 IDEALIZED，并由门限盯住。
3. **标 BLOCKED，继续往下做。** 实在不行，记录原因，先做后面不依赖它的部分。

只有环境坏了（工具不可用、文件丢失）才停下来向你报告。

## 推进过程中你能看到什么

你不需要盯着，但随时可以看：

- **`gates/<阶段>.json`**：每道门最近一次的判定和证据文件路径。
- **`stage-log.md`**：每个阶段的实测耗时、门失败、返工、人工介入和卡点细节。
- **进展截图**：大项目开发中途不渲成片，而是在已装配的场景上换机位渲关键帧，拼成带说明的 WebP（例如[全流程实验室](/cases/full-lab)的各期进展图）。
- 想知道进展，直接问「现在进展到哪了」即可。

## 授权全程自主

任务很长时，你可以提前把所有决定说清楚，授权全程自主运行。全流程实验室就是这样：两个审批点改为 agent 自审，页面照常发布留档；卡住按上面的顺序处理；结束时一次性交付成片、学习页和复盘。这种授权只对那一个项目有效，新项目仍按三次出场来。
