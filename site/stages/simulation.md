# 06 仿真

<StageHeader stage="simulation" />

仿真阶段把复用资产和新建资产装配成一个 MuJoCo 场景，规划机械臂轨迹，跑名义流程和全部负例，用 plan 冻结的门限判定，并把每个刚体每一帧的位姿记录下来交给渲染。

**这是问题最多的阶段。** 薄切片 01 在这里返工了 14 次，名义流程连续 7 次 FAIL 才 PASS，还有一个负例没有触发。前面阶段没暴露的几何、布局、控制、数值问题会在这里集中出现。所以这一页的重点是**顺序**：越便宜的检查越先做。

## 动作是「算出来」的，不是「摆出来」的

控制器只给电机下目标（关节位置），板、盖、管怎么动，全部由 MuJoCo 每 0.5 ms 一步按重力、接触、摩擦算出来。夹得太松板会下滑，放偏了会卡住或倾斜，门没开就伸手会撞上门，这些都会如实发生并被测量出来。从控制器到状态记录之间，没有任何一步是人直接摆位置的。

## 标准做法（按顺序）

1. **用 MjSpec 装配场景。** 注意 `attach_body` 只带入 body 子树，源文件里的 `<exclude>` 不会跟过来（门因此和箱体卡在 51.7°）；子 body 会继承 frame 的旋转（观察站转了 −90°，板也跟着转了 90°，夹爪于是面对短边）。
2. **关键位姿用多初值、带碰撞检查的 IK**：只接受与环境无接触（留 5 mm 裕度）的解，再从中选离舒适姿态最近的。大范围移动用关节插值，短距离直线动作才做笛卡尔跟踪。
3. **先做运动学初筛，再跑动力学。** 沿参考轨迹逐帧摆好关节姿态，查机器人与环境、门和抽屉扫掠与静态环境。整条轨迹查一遍约 8 s，跑一次动力学约 2 min，出了问题也更难定位。
4. **搬带盖工件时，手爪只允许绕竖直轴转动**：用「绕底座竖轴的圆弧加偏航插值」，不要用关节插值，否则工件会倾斜、盖会滑落。
5. **布局按可达性定。** 取、放都应该让手爪径向朝外；出现「伸过去再回头」的姿态说明布局有问题。Panda 手爪水平朝外、手掌朝上时，TCP 高出基座 0.18–0.34 m 这一段 j6 会顶到下限，IK 无解，所有取放高度要落在同一条可解的高度带里。
6. **控制**：位置执行器加加速度前馈 `ctrl = q_ref + (kv/kp)·q̇_ref`；机器人开重力补偿；复用设备的驱动参数要核对稳态误差；自建位置执行器必须设 `biastype="affine"`。
7. **接触数值**：开 `noslip_iterations`；夹持接触用更硬的 solref（0.002）；几克重的小件用 0.004；夹持力和穿透门限一起调；**不往下丢东西**。
8. **测量代码对照门限原文写。** 写错了改代码，不改门限。

第 6、7 条背后的物理，在[物理实验台](/physics/contact)里可以直接在浏览器里跑 MuJoCo 看到。

## 一次完整的诊断：配平管为什么撞上杯壁 {#diagnosis}

全流程实验室第 3 期，配平管放回侧架时 S3 = 2.04 mm，接触对是管底和侧架杯壁。诊断过程值得完整看一遍，因为它展示了「先测量、再假设、错了就如实记录」的做法：

1. **加测量，不猜。** 开一个调试窗口，每 0.05 s 记录管相对手的姿态。取管时姿态正确，之后在两段里逐渐偏开：抽管时管壁擦孔壁，以及手转身调姿。
2. **假设 1（错）**：手指一直顶着盖。让被抓件不和手指做接触，重跑，结果和之前逐位相同，假设不成立。这个改动保留（weld 已经代表抓取），但如实记为「猜错了」。
3. **根因**：weld 挂在「手 → 3 g 的盖 → 7 g 的管」这条链上。MuJoCo 的软约束按惯量缩放刚度，最轻的盖这一环偏得最多，最大到 2°。改成手直接约束管身，倾斜降到 0.34°。
4. **剩下的 2.3 mm 横偏**来自离心后盖相对管身的累积错位。设计修订：侧架杯壁间隙从 1 mm 放宽到 3 mm（管底方垫半宽 5 mm、座面半宽 12.5 mm，偏 3 mm 仍完全落在座面上）。
5. 结果：S3 降到 0.20 mm，第 3 期 19 项门限全部 PASS，负例 N7、N8、N9 按预期判 FAIL。

注意改的是**设计**（约束挂法、杯壁间隙），门限 S3 一直是 0.25 mm。这条约束链的现象在[执行器与约束](/physics/actuators)里可以复现。

## 产物与验证门

- `scene.py`（MjSpec 装配）、`plan_motion.py`（IK、轨迹、运动学初筛）、`run_flow.py` 或 `run_*.py`（动力学运行和门限评估）；
- `results/nominal.json` 和每个负例的 `results/<变体>.json`；
- `states_30fps.npz`：渲染用的刚体位姿，按 30 fps 网格采样；`scene_layout.json`：交给渲染的布局和相机参数。

```bash
uv run --extra sim wb gate <项目> simulation
```

- 名义流程的全部门限 PASS（分期项目按期累加）；
- 每个负例都按预期判 FAIL（没触发的负例会让整道门 FAIL）；
- 渲染用位姿记录存在。
