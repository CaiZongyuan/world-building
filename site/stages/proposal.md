# 02 方案预览

<StageHeader stage="proposal" />

方案预览产出一页本地 HTML，让工程师在开工前把方案看透：要哪些设备、场景怎么摆、工艺怎么走、难在哪里。更重要的是，这一步要**用事实核查需求**，把需求访谈里没查过的物理约束暴露出来，再交给审批点①。

## 方案页的 8 节

页面有 8 个固定小节，`id` 依次为 `goal / renders / layout / devices / steps / stages / risks / references`。设备、工艺步骤、外部参考三张表的数据写在 `<script type="application/json" id="proposal-data">` 里，由页面渲染成表格，验证门也直接解析这段 JSON。

页面最上方是**工程决策**框：夹具、层位、布局、尺寸这些决定由 agent 自己做，每项附原因和证据，**不列成「请用户确认」**。审批点只问方向性问题。

其他要求：

- **设备状态如实标注。** 只编译通过不能写成 PASS；理想化的部件标 IDEALIZED。每台设备还要有难度等级和许可。
- **外部参考只引用文字和数据**，不嵌入外部图片；每条标明许可，以及是「仅参考」还是「可作资产」。
- **效果图标明「概念图，不是工程图」。** 用 imagegen 后台并行生成，提示词只写通用描述（例如 "white seven-axis collaborative robot arm"），不写品牌名，不出现文字和 logo。
- **图片一律用 WebP。** 薄切片 01 的 3 张效果图加 6 张缩略图共约 280 KB，用 PNG 时约 6 MB。
- **样式沿用模板**：把仓库的 `templates/proposal/assets/` 复制到 `02-proposal/assets/`。浅色、深色两套主题都要截图自查，URL 加 `?theme=light` 可强制浅色。

## 运动学预演：开工前先摆一遍 {#preflight}

这是方案预览里最重要的一步，也是从教训里加上的。薄切片 01 仿真阶段返工了 14 次，其中 9 次是**运动学可行性**问题：夹爪行程比工件小、伸入深度不够、外门扫到机器人底座、放板位置够不着……这些都不需要算力，只要把位姿摆出来就能发现，却拖到了最贵的动力学阶段才暴露。当时的方案预览只用 IK 查了点位能否到达，没有查工具几何、进出方向和设备扫掠。

现在的做法：

1. 设备、工件、夹具全部用**方盒代理**表示，**尺寸取自真实资产**（代理偏大会产生大量误报）。
2. 用**多初值、带碰撞检查的 IK** 解出每个取、放位姿，写明进出方向和夹爪张合轴。
3. 做两类**扫掠**：机器人对环境；门、抽屉对静态环境。
4. 结论写进方案页的「工程决策」。

```bash
uv run --extra sim wb preflight 02-proposal/analysis/preflight.json --out 02-proposal/analysis
```

它输出 `preflight_report.json` 和俯视图，结果分四类：**G** 夹爪行程、**P** 关键位姿（含进出段）、**D** 活动件扫掠、**T** 位姿之间的过渡。下面是全流程实验室最终布局（v3）的真实预演结果：

几个数字可以帮你建立直觉：

- 每跑一版只要 40–63 s。全流程实验室第一版 33 项里 11 项失败，第二版 10 项，第三版 57 项全部通过。
- 拿薄切片 01 做回放检验：旧的 P3 布局加原装夹爪，预演判 7 项 FAIL，正是当年在仿真里返工了好几轮的那些问题；薄切片 01 的最终布局 6 项全部 PASS，约 5 秒。
- v3 按工艺顺序生成了完整的机器人路线（12 个取放位姿、9 个门口过渡点、27 段过渡），仿真阶段直接沿用。

预演工具本身也在回放中修过几处误报，现在已经是默认行为：贴着支撑面的夹取位姿余量按位姿放宽；两指夹爪绕进入方向转 180° 视为同一个抓取（偏置宽指这种不对称夹具要标 `symmetric: false`）；每个位姿保留多组构型、默认试 200 个初值，避免把「过渡走不通」误判成「位姿不可行」。

`preflight.json` 的完整字段见仓库 `docs/agents/project-layout.md`。

## 发布和审批

```bash
uv run wb publish <项目>
```

把 `02-proposal/` 复制到仓库的 `proposals/<项目名>/`，方便直接浏览和对比各个版本（这是「项目产物只放 HF」的唯一例外）。方案页每改一次都要重新发布、再提交。然后请你审批（审批点①），看什么见[审批时看什么](/skill/review)。

## 验证门查什么

- 方案页存在，8 节齐全；
- 图片本地化（没有外链）、文件存在、格式为 WebP；
- 结构化数据可解析：设备有状态、难度等级、许可；工艺步骤有难度等级和保真度；外部素材有来源、许可、用途；设备缩略图本地存在且为 WebP。

## 踩过的坑

- **把工程细节当成审批事项。** 第一版把夹爪、层位、外形尺寸列成「请用户确认」。用户的反馈是：具体的尺寸问题需要 agent 自己解决。
- **写了时间预估。** 用户要求只按阶段、步骤、难度组织；现在 plan 的验证门会检查时间预估字样。
- **夹爪行程和工件尺寸不匹配。** Panda 原装夹爪行程 80 mm，六孔板宽 85.5 mm，原装手指根本夹不住。需求访谈时推荐的「先用原装手指」是错的。凡是涉及抓取，最早就要核对夹爪行程和工件尺寸。
- **「沿用旧布局」不等于「沿用旧布局下可达的那个位姿」。** P3 取的是最上层、靠门的板，换成中层或靠里的板就够不到了。
- **实查改变设计。** 全流程实验室实查发现工作站 Z 行程只有 75 mm，吸头够不着 15 mL 管，要加长 Z 轴；离心机是 30° 固定角转子，装管要沿孔轴插入，于是采用转子分度。
