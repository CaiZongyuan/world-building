# 一个物体由什么组成

建模和仿真阶段的大部分问题，都出在物理模型的细节上。这一部分把需要懂的物理讲清楚，每个要点都配了一个**实验台**：改一个参数、按运行、看门限判 PASS 还是 FAIL。实验台直接在你的浏览器里运行 MuJoCo 3.17（WebAssembly），引擎加载不了时会自动切换为预计算回放，数据是同一份模型用本地 MuJoCo 跑出来的。

::: tip 这一部分怎么读
按顺序读：先认识模型由什么组成（本页），再看接触和摩擦，然后是执行器和约束，最后是物理测试怎么做。每个实验台旁边都写了「试试这样做」。
:::

## MJCF 里的六种元素

建模阶段做两份模型：Blender 视觉模型给渲染用，MuJoCo 物理模型（MJCF）给仿真用。物理模型里，一个东西由下面几种元素组成。把鼠标移到左边的条目上，右边对应的 XML 会高亮：

<Anatomy />

几个名字前缀会在实验台里反复出现：`obj_` 是工件，`sup_` 是支撑面，`pad_` 是夹持面，`fix_` 是固定物。门限的测量代码按这些前缀挑选接触对，例如 S3 统计的是工件和固定物之间的穿透。

## 视觉与碰撞分开

渲染要好看，用精细网格；仿真要稳、要快，只用简单的基本形状拼出**碰撞代理**。两者完全分开：`VIS_` 是视觉，`COL_` 是碰撞，`ROOT_` 是根对象。导出 GLB 时按白名单只带走视觉，渲染场景里一个碰撞代理也不许有（渲染门 V1）。

为什么碰撞一定要用基本形状：

- **接触数决定速度。** 盖子压在整块垫台上时，盖内几百个加强筋小凸块全部接触，产生 444 个接触，实时因子从 0.2 掉到 0.02。改成两根窄条只托住盖裙后恢复。
- **形状决定能不能站稳。** 圆柱对圆柱只有一个接触点，管子会被推倒；改成方垫加杯壁才立得住。
- **碰撞代理只保留功能面：** 支撑面、夹持面、导向面。和功能无关的细节一律不进物理模型。

## 哪些东西之间会碰：contype 与 conaffinity

两个 geom 只有满足 `(A.contype & B.conaffinity) || (B.contype & A.conaffinity)` 时才检测接触。勾选下面的位试试：

<ContactBits />

项目里的典型用法：

- 让被夹的工件不和手指做接触（抓取由 weld 代表）；
- 离心机盖由舵机保持，和机身排除接触（否则 416 个接触，实时因子跌到 0.026）；
- 吸头和离心管之间排除接触，「是否插在管口内」由门限 S18 按几何判定。

还有一个坑：MjSpec 的 `attach_body` 组装资产时不会带入源文件的 `<exclude>`，门因此和箱体卡在 51.7°，要在场景里显式补上。

## 七个实验台

| 实验 | 讲什么 | 在哪 |
|---|---|---|
| 1 软接触 | 放下一块板会陷进去多少 | [接触、摩擦与对中](./contact) |
| 2 摩擦夹持 | 夹多紧才不掉、又不压穿 | [接触、摩擦与对中](./contact#grip) |
| 3 对中 | 平夹块 vs V 形夹块 | [接触、摩擦与对中](./contact#vjaw) |

| 5 weld 约束链 | 最轻的件放在中间会怎样 | [执行器与约束](./actuators#weld) |
| 6 跑一次门限 | 名义流程 vs 负例 | [仿真阶段](/stages/simulation) |
| 7 状态接力 | 分两段跑，能不能和一次跑完一样 | [物理测试怎么做](./testing#chain) |

每个实验也能在本机 MuJoCo 窗口里播放，用的是同一份定义 `site/labs/labs.json`：

```bash
uv run --extra sim python site/labs/play.py --list             # 列出全部实验和参数
uv run --extra sim python site/labs/play.py vjaw shape=0 mu=2   # 参数取选项序号，和网页按钮顺序一致
```

改了实验定义，要用 `uv run --extra sim python site/labs/runner.py` 重新生成预计算回放（`site/labs/fallback/`）。
